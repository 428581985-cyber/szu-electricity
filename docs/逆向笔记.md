# 逆向笔记：cgcSims 服务端的脾气

> 这些是实测出来的服务端事实，改代码前务必先看这张表。零散、但每条都踩过。
> 想看怎么用，回 [README](../README.md)。

## 一、接口只有两个

| 接口 | 方法 | 作用 |
|---|---|---|
| `/cgcSims/login.do` | POST | 用 `(buildingId, roomName)` 登录，返回带 `roomId` 隐藏字段的查询页 |
| `/cgcSims/selectList.do` | POST | 查记录，`type=2` 用电、`type=1` 购电 |

扒遍了其它路径：12 个候选「实时读数」接口全是 404/500，**这个系统没有实时读数**。

## 一点五、`client` 是**校区编号**，不是你的 IP

登录页自带一张 `client` 下拉，值长得很像 IP，其实是**校区/片区的固定编号**：

| 校区 | `client` 值 |
|---|---|
| 北校区 | `192.168.84.1` |
| 南校区 | `192.168.84.110` |
| 西丽校区 | `172.21.101.11` |
| 深大新斋区 | `192.168.84.87` |

**关键结论：楼栋下拉是跟着校区变的**（实测）：

- 北校区（默认）= **33 栋**（乔林/乔木/乔森阁/乔相阁…那批）
- 南校区 = **9 栋**（春笛/夏筝/秋瑟/冬筑…那批）
- 同一个编号在不同校区可能是不同的楼：`6875` 在南区叫「春笛3-8楼」，在北区叫「乔森阁2-10层」

所以「先选校区、再选楼栋」不是 UI 偏好，是**必须的**；先选错校区就会拿到一份不属于自己的楼栋表。
`scraper.py` 里那张 `_BUILDINGS` 只是**探测不到服务器时的兜底**，正常走 `/api/detect` 现取。

## 二、登录这条路

| 现象 | 结论 |
|---|---|
| 想用一条链接直接进宿舍页 | **做不到**。把 `client/buildingId/buildingName/roomName/select` 全塞进 GET 查询串，照样返回登录页。登录**只能靠 POST** |
| 全新会话直接 POST `login.do`（不先 GET） | 能登录成功，返回页含 `selectListForm` + `roomId` 隐藏字段。所以浏览器里自动 POST 一次就够了 |
| `buildingName` 传什么 | **传空串最稳**。服务端靠 `(buildingId, roomName)` 定位房间，那个隐藏字段学生根本不用填 |
| 「登录页显示的名字被拒、必须传内部名」 | ❌ 早期结论，**已被推翻**。当时是房间号不在该层段，跟名字无关 |
| 跨源 POST 到校内服务器 | 可行，且 **Referer 不参与校验**（本地页面 POST 过去照样登录成功） |
| 落地页表单的 action 带 `;jsessionid=xxx` | 首次无 cookie 请求时 Tomcat 把会话写进 URL，所以落地页上直接点「查询」不用再登录 |
| 登录页的楼栋下拉 | **按校区不同**（见第一节五）。取楼栋表要带上 `client` 再 GET 一次 |

## 三、查询这条路

| 现象 | 结论 |
|---|---|
| 未登录直接 POST `selectList.do` | **不会**被打回登录页，而是返回一个「没有数据的查询页」——看着正常，其实空。判登录态只能看响应里有没有 `loginForm` |
| 查询阶段传 `building` | 完全被忽略，唯一过滤条件是 `roomId` |
| 每页多少条 | 固定 19 条，翻页靠 `POST selectList.do?pageNo=N`（表单字段不变） |
| 响应编码 | `gb2312`/`gbk`，按 charset 解码，遇到 `iso-8859-1` 也按 gbk 兜底 |
| 表格结构 | 按**表头文本**定位列，不要正则硬匹配 `<td width="13%">`（学校一改列宽就崩） |
| 购电记录里的「购买者」 | 实际是**充值流水号**，不是人。同一人连续充值会产生连续号段，甚至同一秒两个号。接口里没有任何标识人的字段（无姓名/学号/一卡通号）→ 本工具不记录、不展示、不统计购电人 |

## 四、楼栋与房间（最容易踩的一节）

几栋楼被学校**按层拆成互不通用的多段**，每段是独立楼栋，**房号不通用**：

- 「乔相阁 2-10 层」的 301 和「乔相阁 11-20 层」的 301 是**两间不同的房**；
- 拿 4 层的房间号去撞「冬筑15-17楼」这种层段，房间压根不存在 → 登录被拒。
  **这是最容易误判成「楼栋名不对」的坑**（我为此卡了很久，换了 4 个校区、试了 8 种名字拼法全失败，
  真正的原因只是房号落在别的层段）。

实测样本（房号是测试时随手取的，非任何人宿舍）：

| 楼栋 | 该段房号示例 | 服务端返回的内部 `roomId` |
|---|---|---|
| 冬筑7-10楼 (8240) | 701 | 8296 |
| 冬筑11-14楼 (8241) | 1101 | 8490 |
| 冬筑15-17楼 (8242) | 1501 | 8695 |

其它结论：

- `roomId` **是派生值**：登录页按房间名匹配后回传，**不写进配置**。写了旧的 `roomId`，换宿舍后会静默查到上一个房间（查到错的还不报错）。
- 填一个不存在的房号（如 `9999`）：**登录成功**，但查不到任何数据。所以「登录成功 ≠ 房间对」，
  报错信息必须说清是房间对不上，而不是含糊的"登录失败"。
- 不要「失败后继续遍历其它楼栋」：那样会静默返回另一个层段的数据，数字看着正常其实全错。
  只试用户选的那一个楼栋，失败就报错。

## 五、时间：为什么今天永远查不到

**服务端每天只在 23:59 存一次快照。** 今天 23:59 之前，数据表里没有任何今天这一行。

派生出的产品规则（都是被这条逼出来的）：

| 规则 | 理由 |
|---|---|
| 用电侧（趋势图 / 用电记录）结束日期**上限是昨天** | 今天算进来只会多一天空数据 |
| 购电侧（购电记录）**可以选到今天** | 购电是实时入库的，今天的购电现在就有 |
| 「当前余额」卡片下面标 `截至 YYYY-MM-DD` | 那是那天的**收盘值**，不是此刻的实时读数，不标日期会误导 |
| 「今日用电」卡片默认不出现 | 只在 23:59 之后极短的窗口内有值。**有数据才出现，没数据就彻底消失**，不显示 `—`、不拿昨天的数补位 |
| 购电记录**没有「账户余电」列** | 该列 = 当日总购电量 − 当日总用电量，靠 23:59 的快照算 → 当天的购电行永远算不出来（实测全是 `—`）。一列半空的占位没意义，整列不做 |
| 趋势图第一格没有柱子 | 第一天没有「前一天」可差分，用电量**未知**。填 `0.0` 会把日均从 12.76 拉低到 10.63，所以填 `null`，日均按真实天数算 |

> 一句话原则：**数据源没有的量就是没有，不留占位、不用最接近的已知量冒充。**

## 六、缴费入口为什么只能扫码

学校的微信扫码缴费页会先跳 `open.weixin.qq.com` 的 OAuth 授权，
页面里有：

```js
if (!isWeixin) document.body.innerHTML = '<h4>请在微信客户端打开链接</h4>';
```

**电脑浏览器（不带微信 UA）点开只会看到这一句。** 所以顶栏给的是二维码而不是链接，
二维码由后端 `/api/qrcode.svg` 现渲染（纯 Python 生成 SVG 文本，不依赖 Pillow、前端零依赖）。

## 七、与 2021 年 `ceynri/szu-electricity-reporter` 的差异

老项目（2021-04 停更）是同一次逆向的早期版本。本项目覆盖了它：

- 老项目用正则硬匹配 `<td width="13%">` → 一改列宽就崩；本项目按表头文本定位列。
- 老项目不做翻页 → 超过 19 条被截断；本项目自动翻页。
- 老项目 `requests.post` 不设 timeout、不处理编码 → 中文乱码；本项目显式 timeout + gb2312/gbk 解码。
- 老项目 `while True` + `time.sleep` 常驻 → 笔记本休眠后滞留；本项目单次执行 + 计划任务调度。
- 老项目让用户填 `roomid` / 楼栋 ID → 填错就查到别人房间；本项目只让人填「楼栋 + 门牌号」，
  内部 ID 一律登录后从响应里提取。
- 老项目的 room_id 对照表抄自登录页选项文本，恰好是那批和内部参数对不上的过时标注
  （它把 `6876/6878` 同时标成「西南」和「南校区」，其中「南校区」那栏 id 没跟着改，是错的）。
